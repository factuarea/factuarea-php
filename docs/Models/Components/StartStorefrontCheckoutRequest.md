# StartStorefrontCheckoutRequest

Ask for the payment link of an order so the shopper can pay it. BOTH fields are optional and an EMPTY body is the normal case — what is being asked for already travels in the path: the shop and the order. This body accepts NO amount, NO currency and NO gateway account: the total is computed by the server from the order itself and the account is resolved from the seller configuration, because being able to propose the amount from the browser would be being able to choose the price. An amount that arrives anyway is IGNORED rather than rejected, so a storefront that echoes back the order object it received keeps working. `return_path` is the RELATIVE path of YOUR site the shopper is sent back to after paying — the domain is never taken from the body, it comes from the origins the publishable credential declares — and an ABSOLUTE address is rejected even when it points at your own domain, together with a query string, a fragment, braces, a `..` segment, a double leading slash, a backslash, control characters and anything longer than 512 characters. Omitted, the path configured for the storefront is used (`/pedido` by default). `full_invoice_requested` says whether the shopper is asking for a full invoice instead of a simplified one, which raises the identity bar. Asking twice within the validity of the link returns the SAME address and the same expiry instead of opening a second payment session.
