# UpdateStorefrontSessionRequest

Partially update a cart session: every field is optional, what you do not send is not touched, and an EMPTY body is a valid request that changes nothing — it is how you check that the cart is still alive without touching it. `lines`, when it travels, REPLACES the whole collection: it is the cart exactly as it stands, not an addition and not a tweak of one line, and an empty list empties the cart. It works that way because a cart is a short list the storefront already has whole on screen, and a language of per-line tweaks would let the screen and the server drift apart without anybody noticing. Each line takes the same shape as on creation and the ceiling of 50 lines still applies. THE PRICE IS NOT SENT: no amount field is accepted and one that arrives is ignored; changing the lines makes the server resolve the amount of each one again and keep it with the moment it was resolved. The buyer is given WHOLE: as soon as any of its fields travels, `buyer_name`, `buyer_email` and the shipping address become required, and sending nothing about the buyer leaves the one the cart already had. A cart that has EXPIRED, one already turned into an ORDER and one that was ABANDONED each reject this call saying which of the three happened, because the remedy of each one is different: open another cart, read the order that already exists, or start again. A cart of another shop answers as not found, with no effect and without revealing that it is there.
