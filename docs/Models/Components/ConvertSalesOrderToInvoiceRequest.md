# ConvertSalesOrderToInvoiceRequest

Invoice a sales order, in full or in part. The line selection travels as a MAP of line identifier to quantity, for example `{"lines": {"0199aa00-0000-7000-8000-000000000001": "3.0000"}}`. The key of each entry is the PUBLIC IDENTIFIER of the order line — the same `id` the lines sub-resource returns — never its position in the list and never an internal identifier; it is a map and not a list of objects so that two entries for the same line are impossible by construction. `lines` is OPTIONAL: omitting it, or sending it empty, invoices EVERYTHING the order has pending invoicing, which is what has already been served and not yet invoiced, because an order is served before it is invoiced. An order with nothing pending invoicing is rejected as a business-rule violation and creates no invoice. `target_series_id` is optional and drives the numbering of the invoice created: it must be a live INVOICE series of the same company, and omitting it numbers with the default invoice series. Each quantity is a positive number with at most four decimals; zero and negative are rejected, because invoicing zero is not invoicing. What this body does not decide is checked afterwards against the order and rejected as a business-rule violation before any invoice is created and before any series number is consumed: that the line belongs to THIS order, that the order may be invoiced, that the quantity does not exceed what is pending invoicing on that line, and that the buyer carries a tax ID when the amount requires one. An order accepts SEVERAL invoices over its life and its status is derived from the resulting quantities. The operation is irreversible.
