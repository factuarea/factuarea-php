# UpdateCarrierRequest

Partially update a carrier of the company master data.

Every field is optional and an empty body changes nothing and is not an error.
What you leave out keeps the value it has, so changing the name touches
neither the code, nor the tracking kind, nor the contact. There is no full
replacement operation: this is the only way to edit a carrier.

A field that is SENT and a field that is LEFT OUT mean two different things,
and the difference is the whole point of this operation. Leaving a key out
keeps the current value; sending it as `null` clears it. An empty string is
neither of the two and is rejected naming the field, so that a form that
blanks a text box cannot wipe the template or the contact of a carrier without
anybody having asked for it.

`name`, `code` and `tracking_kind` cannot be cleared: a carrier without a
name, without a code or without a tracking kind is not a carrier, so sending
any of the three as `null` or empty is rejected. Whoever does not want to
change them leaves them out. A new `code` keeps the same uniqueness rule as
creation, unique within the company, and resending the code the carrier
already holds is legitimate and collides with nothing.

`tracking_url_template` may be sent, cleared or left alone, and it is checked
the same way as on creation: it has to carry the `{tracking_number}`
placeholder and its scheme has to be `http` or `https`. Moving the carrier to
the `url_template` kind and clearing the template in the same request is
rejected, because that pair would promise a tracking link and hold nothing to
build it with; moving it to that kind WITHOUT touching the template is
accepted when the carrier already holds one and rejected as a business rule
violation when it does not.

`contact` is one piece: sending it REPLACES the whole block, so a key left out
inside it is cleared, and sending `contact` as `null` withdraws the contact
altogether. It is published the same way, as one object with `name`, `email`
and `phone`, so what you send and what you read back have the same shape.

`is_active` withdraws the carrier from service without deleting it: a
withdrawn carrier is still readable, still resolves the tracking address of
the delivery notes that already reference it, and merely stops being
assignable to a new shipment. It takes `true` or `false` and never `null`.

The body takes neither the company, which comes from the path, nor the
identifier of the carrier, which the route carries. Internal notes are not
part of the published carrier and are not accepted here either.
