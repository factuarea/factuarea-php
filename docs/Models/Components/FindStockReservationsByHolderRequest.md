# FindStockReservationsByHolderRequest

Look up everything a holder is keeping on hold. The holder is a PAIR: `holder_type` (the short name you used when reserving — lowercase letters, digits and underscore, up to 40 characters; it is not a closed catalogue, you choose it) and `holder_id` (its public ID, UUID). Both are required and both travel in the body, because neither one owns the other and an identifier may carry characters a path segment would break. The response lists the reservations of that holder within the company in the path. A holder of another company, one that never reserved anything and a mistyped pair all answer the same — no reservations — with no way to tell the three apart. It changes nothing: repeating it has no effect and consumes no idempotency key.
