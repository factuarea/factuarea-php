# ConfirmStorefrontCheckoutRequest

Confirm, right after the shopper comes back from the gateway, that the payment session was really paid — and get the state of the order and its invoice. `session_id` is REQUIRED: it is the identifier the gateway itself puts in the return address, it starts with `cs_` and is at most 255 characters long. Nothing else travels in the body: neither the amount, nor the currency, nor the account, because what is being confirmed is read from the gateway and never taken from the browser. A session that cannot be verified, or one that belongs to a DIFFERENT order, changes nothing and answers with the current state of the order rather than with an error, so probing identifiers tells the caller nothing. The `Idempotency-Key` HEADER IS REQUIRED here, because a confirmation issues the invoice of the order — a fiscal document with a sequential number that can only be undone with a corrective one: the same key with the same body replays the SAME answer and leaves ONE single invoice. Confirming an order that is already paid is not an error either: it answers what it already knows.
