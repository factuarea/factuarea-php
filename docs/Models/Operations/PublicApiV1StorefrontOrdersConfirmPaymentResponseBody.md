                                                                                                                                                                                     | The outcome of confirming the collection of an order: where the collection stands, where the order stands and which invoice was issued. A guard that is NOT met is not an error and has no public code: when the payment session cannot be read, is not paid, or does not belong to THAT order, nothing is marked and this same body publishes the CURRENT situation of the order — there is no "reason" key on purpose, because publishing one would turn the answer into an oracle for finding out, by trying session identifiers, which one belongs to which order. The reason is logged instead, with the order and the session and with no data of the credential or of the means of payment. Confirming is repeatable: the same confirmation twice records one single payment and answers the same thing. |
