## publicApiV1WarehousesDelete

Archive a warehouse. The operation RETIRES the warehouse from the operation and does NOT delete its row: the warehouse and its history are preserved, so the documents, the stock movements and the transfers that point at it keep pointing at something. It stops being returned among the active ones and its code is freed, so a later creation of the same company can reuse it. A warehouse that is still occupied is not archived: one with active locations, or one taking part as origin or destination in a transfer that has not reached a terminal status, returns 422 with the code that names that condition. Archiving the warehouse that was the default one leaves the company without a default — no other warehouse inherits the mark — and the default read starts failing until you set a new one. It returns no content. Irreversible: this API publishes no operation that brings an archived warehouse back, so it requires an `Idempotency-Key` when the policy of your credential demands it.

## publicApiV1WarehousesUpdate

Partially update a warehouse: only the fields present in the body change and the ones you omit keep their value, the address included. The code can be changed and it keeps being unique per company among the active warehouses, so moving it onto one that is already in use returns 422 naming `code`. The default mark is not part of this body: it has its own operation, because marking one warehouse unmarks another and that is a transition, not an edit. An archived warehouse does not accept changes and rejects the call as a business rule violation, with 422 and never 403.

## publicApiV1WarehousesCreate

Create a warehouse with its code, its name, its type — own, external, store or transit —, its full address and, optionally, the mark that makes it the default one of the company. The code is the integration key: required, up to 20 characters and unique per company among the warehouses that are still active, so repeating one that is in use returns 422 naming `code`, never 409. Two different companies can each have their own `MAD-01`, and archiving a warehouse frees its code for a later creation. Marking the new warehouse as the default one unmarks the previous default in the same transaction, so the company never has two. The response is the warehouse that was created, with its public id, its address broken down field by field and the number of locations it has active — none at this point.

## publicApiV1WarehousesDefault

Retrieve the warehouse the company uses by default: the one the operations that do not name a warehouse fall back on. A company that has no default warehouse does not get a 200 with an empty body — that would read as "no warehouse needed", which is the opposite of what the rule says — and does not get a 404 either, because nothing you named is missing: it returns 422 with the code that says the warehouse cannot be resolved, naming the warehouse field, so you can set one and retry.

## publicApiV1WarehousesMarkAsDefault

Make a warehouse the default one of the company. It takes no body. The warehouse that was the default is unmarked in the same transaction, so the company never has two, and marking the one that is already marked changes nothing and is safe to repeat. It is not published as irreversible, because marking another warehouse moves the mark back. Returns the warehouse with its default mark set.
