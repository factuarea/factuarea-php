# Private Native149 PHP consumers

`Factuarea\Sdk\NativeCrm134\SourceClient::privateContract($sdk)` explicitly selects the unreleased Stage, ticket Bulk and Library restore Original consumers. The existing Composer PSR-4 map already resolves this namespace; no normal client alias, public spec or Native139/143 class is replaced.

Generation consumes the actual Native149 PASS attempt6 export after shared151 and causal154/156: SHA-256 `3667e01b82dea255c23b2eecb80e6e600baa445b5b7a2beb5a65eb978a1fc073`, 967 operations, 372 carriers, catalog `f033c9debb1e41c21bba79bb57de9ff3a23370befdc1aa13a4e7e48b653dbcd3`. The literal Root consumer manifest is retained unchanged at `spec/crm-native134-consumer-manifest.json`, SHA-256 `653247d4492095fb40e06c36e20a61ec4e0ba32165d0f393378eeffe9872d901`. The provenance and transitive schema cache bind those exact bytes. The SourceClient verifies source, schema cache and consumer manifest hashes before selecting the existing transport with current security. `published=false`, `ratified=false`, `capabilities=[]`, delivery disabled. Selecting this PHP namespace does not grant permissions or activate backend functionality.

The seven generated operation methods retain native HTTP verbs, paths, public UUID fields, integer CAS values, omitted fields, explicit null, success200 and distinct fine/OAuth scopes. The restore POST request/result DTOs are generated for validation and compatibility only; the Library has no new restore POST method. The normal and historical profiles keep their previous validator behavior. Only the new schema profile translates its native JSON Schema control escapes to PCRE syntax; the producer schemas remain unchanged.

Stage methods are `stageOperations->listServiceStages(...)`, `stageOperations->listServiceStagesItems(...)`, `stages->update(...)` and `stages->original(...)`. The paginated iterator follows the native numbered page envelope and does not infer record access from the returned catalog. Listing uses `customer_service:read` / `customer_service.read`; update and Original use `customer_service:write` / `customer_service.write` and the native Company/manageAll/C7 requirements. The server remains the authority for those requirements.

Create `Stages\UpdateIntent::reviewed($stage, $generatedBody, $key)` before dispatch. The intent freezes the six-field body and key before any HTTP attempt. Its `requestFingerprint` implements the native documented normalized seven-field object: lower-case stage/pipeline UUIDs; native integer versions; exact sent name, mapped status and WIP; string-sorted keys and native unescaped Unicode/slash JSON flags. This selector differs from the raw body SHA-256 and includes no authentication data. A second known intent reads Original GET. A restored intent from `Stages\UpdateIntent::restore($stage, $bytes, $sha256, $key)` is readback-only. An uncertain first attempt raises `Stages\UpdateUnconfirmedException` retaining that intent; native4xx errors remain visible. Stage Original409 remains unconfirmed and never triggers another PATCH. Confirmed receipts retain the original stage+1 version, unchanged parent CAS and reviewed configuration even after head drift.

Bulk methods are `bulkOperations->getServiceTicketBulkOptions(...)`, `ticketBulk->apply(...)` and `ticketBulk->originals(...)`. Use the generated closed four-way body variants for `assign`, `priority`, `tags` and `status`, or hydrate the generated `ApplyServiceTicketBulkActionParameters` from the exact typed shape. `Bulk\ApplyIntent::reviewed($parameters)` freezes the action, ordered items, per-item CAS, payload and literal key. Restoring with `Bulk\ApplyIntent::restore($bytes, $sha256, $key)` is readback-only. A first apply returns the actual native bulk envelope; a known/restored apply returns a list of individual Original responses in selection order. Unknown, rejected and confirmed counts remain factual native per-item states; no global durable batch receipt is created by the SDK.

Each Bulk Original GET retains the ticket UUID, original key, action, expected version and same payload. Null assignee is the native textual `null` selector; an empty tag replacement is the native JSON `[]` selector. The SDK does not substitute options or Current for a lost result. Confirmed no-ops can preserve the ticket version. Unknown always carries native `can_retry=false`. A global failure raises `Bulk\ApplyUnconfirmedException` with the retained intent and original failure; recover each item through `originals(...)`. A failed/revoked read exposes the current native error and sends no POST. Catalog reads require `customer_service:read` / `customer_service.read`; mutations and Original use the native write scopes. Catalog visibility does not authorize editing or LeadCapture.

For Library restoration, the existing Native139 namespace still provides the unchanged actual Native143 first POST consumer. Recover its retained `Documents\RestoreIntent` through `Library\RestoreOriginalIntent::fromNative143($intent)` and `restoreOriginal->original($readback)`. Alternatively, restore the exact caller-retained body/hash/key with `Library\RestoreOriginalIntent::restore(...)`; optional version/active-profile headers are retained explicitly. The Native149 POST schema validates explicit `confirmed=true`, closed fields and integer CAS before the GET selector is built. These intents have no dispatch method. Original GET carries only document UUID, expected_version and literal Idempotency-Key; body/hash/effect/blob are not published. Its scope is `crm_documents:read` / `crm_documents.read`, while the native owner additionally reauthorizes current restore access and retained private fields. A confirmed variant exposes the immutable restoration id/version expected+1. An unknown variant preserves `restore_original=null`; a Current read cannot promote it and no POST follows.

All new methods reuse the existing configured HTTP client, hooks, current security and error hierarchy. Mutating requests make one factual send; Original reads remain GET with no body and retained method/path/key protection. Redirects are disabled for the private profile. The SDK stores no authority or durable receipt. Callers retain the intent bytes/hash/key across process restarts.

Private generation:

```bash
python3 tools/generate-crm.py --private-source134 NATIVE149_INPUT_MANIFEST \
  --sdk-root EXISTING_SDK_ROOT --packet-root DURABLE_PRIVATE_PACKET_ROOT
```

The generator verifies literal artifact and Root selection bytes, writes only new `src/NativeCrm134` leaves directly, and puts existing SDK-path inputs/metadata under the private packet's `old/post/spec`. Handwritten intent adapters remain outside regeneration. Root performs the serial private mount. No installation, external API call, publication, activation or test result is certified by these consumers.

El export completo `spec/crm-native134-source.json` es un input privado de regeneración, conservado fuera de Git. El consumidor instalado requiere los DTO y caches/manifiesto versionados; valida el hash de origen en la cache y, si existe el input completo local, también valida sus bytes. No necesita el export completo para ejecutar las siete operaciones.
