# Private native CRM Source profile

`Factuarea\Sdk\Custom\Crm\Native139\SourceClient::privateContract($sdk)` explicitly selects the unreleased native Source export. The normal `CrmClient`, public spec pins, generated Speakeasy consumers and SDK110 export aliases retain their existing contract.

The exact native export is stored at `spec/crm-native139-source.json`, with its producer hash and OFF profile at `spec/crm-native139-provenance.json`. The namespace and filenames retain their original name; the current producer is actual Source143, SHA-256 `59b6cd2664aa8524e96a7600565b70b5eae5f6beaa7527913d703adf653a2fca`, with 959 operations and 364 carriers. The earlier Source139 implementation remains in commit `979e9928b94303befede83c258d6f3ae9c6e6003`. Generation consumes the literal current export; no schema or missing endpoint is supplied by hand. This is unreleased Source metadata, with `published=false`, `ratified=false`, capabilities empty and delivery disabled. Selecting the PHP namespace does not change backend flags, plans, scopes or grants.

```bash
python3 tools/generate-crm.py --private-source139 spec/crm-native139-provenance.json
```

The mode writes only `Native139`, its private source/provenance, `crm-native139-operations.json` and `crm-native139-schemas.json`. The latter contains the unchanged native schema definitions transitively reached by generated DTOs; its hash is retained beside the literal export hash. Validation loads this smaller derived cache instead of parsing unrelated operations. The normal generator input/output remains separate. Its operations inventory records native paths, methods and declared fine/OAuth scopes; missing OAuth metadata is retained as absent, never inferred from a fine scope.

The native generated ContactPeople, Leads, Pipelines, KnowledgeBase and PublicHelpCenter clients use the existing HTTP/auth/hooks/error transport. Opportunities and Activities expose the exact native create, create Original, Current and list operations at the singular `/crm/opportunity` and `/crm/crmactivity` paths. Their Original reads use the retained write key and exact body hash under writer scopes; Current/list use their separate reader scopes. Creation never retries a POST, and a lost response is recovered with the generated Original GET. An Activity task alias does not establish Task availability or creation.

The private profile resolves configured security immediately before each factual attempt and accepts only the success statuses actually declared by that operation. Owner UUIDs, versions, decimal strings, omitted fields and explicit null remain governed by the native schemas and server authority.

For a first import application, supply the actual generated `PublicApiV1CrmSpreadsheetImportsApplyParametersBody`, including explicit `confirmed=true`, to `ApplyIntent::reviewed($run, $body, $key)`, then call `imports->apply($intent)`. The intent freezes exact serialized bytes before dispatch; later changes to the original DTO cannot alter them. Native validation preserves CAS, preview hash, UUIDv7 effect, closed fields and the `retry_failed`-only corrected blob. The caller retains the bytes, SHA-256 and key. Although the native POST policy accepts an omitted key, this recoverable SDK path requires one. A native202 is an accepted run snapshot with factual pending progress, including an authorized retry child; it never means every row completed.

The same known intent reads `GET crm/imports/{run}/apply/original` with the retained key and `original_body_sha256` query. `ApplyIntent::restore(...)` is readback-only across process restarts, including originally retained whitespace and property order. The earlier `ApplyOriginalIntent::restore(...)` and `imports->original(...)` remain available. Missing, in-progress and unconfirmed results preserve a null original response and never grant a resend. Confirmed results retain the exact original202 response string. An ambiguous first dispatch raises `ApplyUnconfirmedException` with that same retained intent. `imports->current(...)` returns the actual typed run and error-page DTO under its separate reader scope, and never upgrades Original. The native query-mode schema rejects mixed cursor/CSV inputs; the typed Current method consumes the JSON representation. No durable receipt or authority is stored by the SDK.

The six-owner export consumer accepts the existing SDK110 `ExportIntent`; its native request/result models are generated from this private export. The existing resend fence, restored-intent readback and byte/hash/key semantics remain in the SDK110 producer. A repeated known intent reads Original. Only ready allows the existing native CSV stream; decimal bytes are never parsed or converted to floats. Native errors remain visible after current reauthorization.

Documents expose actual current GET/list with native field omission, UUIDv7 and record masks. Agenda exposes the published Query-only `GET agenda`, its native date window, optional sources/assignee and the layers actually served. Served layers neither grant scopes nor establish free/busy or Booking availability.

For document restoration, create `Documents\RestoreIntent::reviewed($document, $generatedBody, $key)` with an explicitly confirmed native CAS body, then call `documentRestores->restore($intent)`. The first200 exposes the actual native id/version receipt. The native owner reauthorizes writer access and the read access needed to observe the postcondition; the SDK does not infer any grant. A first ambiguous result, a retained intent or an already attempted intent raises `RestoreUnconfirmedException`: `outcome=unconfirmed`, `originalState=unknown`, `canReadOriginal=false`. Source143 has no separate restore Original GET. No endpoint is invented, no second POST is emitted and a document Current read cannot confirm that restoration. Restore and Apply preserve their original method, URI, key and body hash across hooks, disable redirects and never retry a POST.

Two HTTP-boundary cases are prepared in `Tests/Custom/Crm/Native139/NativeContract139HttpTest.php`: retained import Original versus Current plus lost Opportunity/Activity creation replies recovered through Original GET with current security; and six-owner CSV recovery alongside current document masks, served agenda layers and a later native403. The first preserves omitted versus null and exact decimal strings, and checks one POST followed only by Original reads. They use Guzzle MockHandler and fixture-only `.invalid` URLs. No tests, runtime, API, database, release or installation were executed or certified during this development.

Two further grouped cases are prepared in `NativeContract143HttpTest.php`: actual Apply202/retry child, immutable reviewed body, closed Current errors, missing/unconfirmed/confirmed Original and current403; and actual restore200 followed by an uncertain restore, Current read, retained-intent stop and rejected redirect. These cases remain unexecuted. Only changed PHP leaves receive the directed formatter/syntax pass; equivalent previously formatted generated tokens are preserved.
